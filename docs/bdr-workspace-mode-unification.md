# Build Decision Record: 一人多 Agent / 多人多 Agent 工作区

1. **真实任务：** 默认工作区只表达通用 Agent Ops；支持一位负责人协调多个专业 Agent，也支持多位人类成员分别持有岗位并与多个 Agent 协作。
2. **最接近的既有能力：** `Project.solo` 已创建一位人类与默认 Agent 集合；`Project.from_spec` 已支持多人、岗位持有人、成员加入/退出和审批 quorum。缺口是默认入口仍指向旧行业规格，WebUI 没有显示工作区模式。
3. **Step 0 判定：** Improve。
3a. **Execution Verdict：** GO。
4. **可度量差异：** 默认入口的项目规格统一为通用负责人；API 返回 human/agent 数量和模式；WebUI 能明确显示“一人多 Agent”或“多人多 Agent”，不再用造价角色代表共享底座。
5. **成功证据：** 默认工作区生成 `P-SAYELF-AGENT-OPS`；团队模板可加载至少两名人类与默认 Agent；模式字段与页面显示有回归测试；全量评估通过。
6. **最小内核：** 既有 Project/Runtime/Workspace API，加上模式计算和通用模板。
7. **插件边界：** 行业 Pack 决定专业 Agent；人类成员只通过显式角色绑定参与相应步骤；不创建组织架构 Agent。
8. **本地优先：** 工作区规格、成员、令牌、工作项和证据留在本机；旧默认目录只做本地可回滚归档。
9. **数据分级：** 模板和源码为 Public；本机成员/工作项为 Sensitive；令牌和模型配置为 Restricted；不提交归档目录。
10. **是否公开发布：** 是，用户已授权同步 GitHub；仅提交通用模板、测试、API/UI 代码和文档。
11. **外发计划：** 推送公开差异；不上传旧工作区、SQLite、模型配置或令牌。
12. **状态与检查：** Solo 表示一位人类负责人 + 多个 Agent；Team 表示多位人类 + 多个 Agent；成员数量或角色变化后重新计算。
13. **观测/推断/假设/事实：** Project 结构已支持两种模式是事实；模式文案是 UI 推断；行业岗位是否可执行仍由 Registry 和路由证据决定。
14. **演进/验证/回滚：** 旧默认目录先归档再重建通用目录；提交可回滚；旧测试规格仅保留在 `evals/fixtures`，不再作为产品模板。
15. **WebUI：** Required；接入页显示当前模式、成员和 Agent 数量，首页保持输入到结果的短路径。
16. **最简实现：** 增加两个模板、一个 `project_view` 模式字段、少量 UI 文案和回归测试；不引入新框架。
17. **明确不做：** 不自动把人类变成 Agent，不自动授予岗位，不删除工作项证据，不把旧造价数据上传或迁移到 GitHub。
