# Build Decision Record: Harness 分派预览与可修改执行

1. **真实任务：** 根据用户描述自动识别交付物，生成可核对的岗位分派方案，允许用户修改输入后重新生成，再选择只查看或开始执行，并在结果页看到可读的工作成果。
2. **最接近的既有能力：** Workspace API 的只读 `/route`、`workflow_contract` 和 `/workitems` 执行入口；缺口是方案没有明确的修改回路，执行前无法确认当前方案仍对应最新输入，成果页也只展示原始 JSON。
3. **Step 0 判定：** Improve。
4. **决策：** 复用共享 Agent Ops/Codex Harness 路由契约；方案卡增加“返回修改”和“按此方案开始执行”，输入变化后使旧方案失效并提示重新生成；结果页按 `content` / `items` 展示成果，并明确区分真实产出和 `placeholder=true` 结构占位。
5. **可度量差异：** 用户可在一次 WebUI 会话内完成 `输入 → 分派预览 → 修改/重新路由 → 执行`；执行只提交当前输入，不提交过期预览。
6. **成功证据：** 路由预览显示识别依据、岗位、技能、工作流校验状态；修改输入后显示重新生成提示；按方案执行成功进入工作项详情并显示可读成果或诚实的结构占位；全量评估通过，媒体标题任务完成一次本地端到端验证。
7. **最小内核：** 既有 `/route`、`/workitems` 和确定性 Router；本次只增加前端状态提示、识别依据、结构化成果渲染，以及行业提示与工作正文分离，不复制执行内核。
8. **Harness 边界：** Codex 读取 `route_task` 同构的岗位、技能、执行合同和证据要求并完成实际工作；WebUI 只负责输入、预览、提交和查看，不调用 `run_task`。
9. **本地优先：** 输入、附件、预览和工作项仍留在本机 Workspace API；不新增远程模型调用或数据上传。
10. **数据分级：** UI 源码、文档和测试为 Public；用户描述、附件和路由结果为本机 Sensitive；凭证仍为 Restricted，不进入页面文本或提交差异。
11. **发布决定：** 用户已授权同步 GitHub；只发布源码、测试和决策文档，不发布本机工作区状态。
12. **状态与检查：** 预览是 read-only；任何行业或工作内容输入变化都会清空旧方案并要求重新路由；执行仍由 Workspace API 再次路由确认。
13. **观测/推断/假设/事实：** 路由结果是确定性推断并显示识别依据；工作流校验是结构事实；带 `placeholder=true` 的结果只是结构占位；真实执行成果和独立复核证据仍按运行状态判定。
14. **演进/回滚：** 前端动作可回滚到原有两个按钮；后端协议不变，旧工作项和证据不改写。
15. **WebUI：** Required；保持 `Open → Input → Execute → Result`，技术细节通过方案卡和渐进提示展示。
16. **最简实现：** 在现有 route card 增加识别依据、动作回调、输入变化失效提示和契约校验显示；在既有详情页增加安全的结构化结果卡片；不引入新框架。
17. **明确不做：** 不允许用户直接改写岗位权限、技能契约或审核门；不把未登记行业临时编造成可执行能力。
