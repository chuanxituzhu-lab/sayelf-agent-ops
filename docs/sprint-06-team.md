# Sprint 06：多人多 Agent（Team）与成员进出（Hybrid）——内核层

> 状态：内核层完成（2026-10-10）。基线：ec923db。验证场：BuildCostIQ 施工项目部模板（`templates/buildcostiq-project-department.json`）。

## 0. 一句话

同一条执行路径，人数大于 1 时自动成为团队：专业岗位由人担任就把那一步交给人，造价发布这类交付需要“造价负责人 + 项目经理”两人各批一次，成员可以加入和退出，历史不改写。单人项目行为不变，四条 Solo 不变式全部仍然通过。

## 1. 决策记录（按 sayelf-base 构建门禁）

1. 任务：让 Agent Ops 从“1 人 + N Agent”扩展到“N 人 + N Agent”，并支持人员动态进出。
2. 最接近的已有能力：`Actor / Project / Policy`（v0.2 已为 Team 预留）、Runtime 按步骤分派岗位（ec923db）、HumanGate 一次性授权与持久化存储。
3. Step 0：**Improve**。不新增模式字段、不另起团队系统，只在同一结构上补“人担任岗位、多人裁决、成员退出”。
4. 可度量差异：施工项目部场景下，图纸比对由技术负责人亲自完成并经独立 Agent 审核；造价对比必须两位不同角色的人分别批准才交付；成员退出后不能再裁决、手上的待办自动交回。
5. 证据：`evals/test_team.py`（19 个用例：结构 3、人工步骤 4、多人裁决 6、成员进出 6），全部 175 个测试通过，含四条 Solo 不变式。
6. 回滚：`git revert`；无数据格式变更。

## 2. 规则

| 能力 | 规则 |
|---|---|
| 人担任岗位 | 某个专业岗位有在职人类成员担任时，计划里这一步交给他（`human-task-assigned`），他提交成果后流程继续；否则交给该岗位的 Agent。单人项目的负责人只持有 owner 角色，所以永远由 Agent 产出——Solo 不变 |
| 产出者不审自己 | 人提交的成果照样先过产出者自检、再由独立审核 Agent 检查；被打回时清掉旧成果，带着审核意见重新交给同一个人 |
| 多人裁决 | `Policy.gate_quorum`：每个角色各由一位**不同的**人批准一次，全部到齐才交付；任何一位驳回即整单退回返工；Agent 永远不计入；批准之间产出被改动会被拦下 |
| 成员管理 | 只有在职负责人（owner）能加人、请人退出；每次变动写入项目日志（谁、何时、对谁） |
| 成员退出 | 标记为不在职，名册与证据链保留；不能再被分派、不能裁决；手上等待中的人工步骤交回，下次运行由新的担任者或 Agent 接手；最后一位负责人不能退出 |
| 团队规格 | `Project.from_spec()` / `to_spec()`：人类成员与裁决规则来自一份 JSON（不含账号、密码、密钥），Agent 岗位按注册表自动补齐 |

- 团队状态（成员、待办、多人审批进度）目前保存在运行进程内；审批记录本身已可持久化（Sprint 03/05 的 SQLite 存储）。
