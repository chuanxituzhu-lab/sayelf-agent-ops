# Build Decision Record: 通用工作台 UI 参考融合

1. **真实任务：** 将外部 UI 参考中的工作台、工作项详情和接入信息层级融合到 Sayelf Agent Ops 的通用 WebUI，让用户能从需求输入一路看到路由、成果、证据和人工审批。
2. **最接近的既有能力：** 现有标准库静态 WebUI、Workspace API、`capabilities`/`project` 接口和工作项证据链；参考图提供布局和信息层级，不提供可复用的运行时。
3. **Step 0 判定：** Integrate。
3a. **Execution Verdict：** GO。
4. **可度量差异：** 在不新增依赖的前提下增加接入入口与详情分栏，工作流关键状态从单页堆叠变成可扫描的步骤、成果、证据、审批四块；通用入口不显示固定造价项目。
5. **成功证据：** 静态 WebUI 回归覆盖新导航、接入页、通用文案；Workspace API 原有 232 项测试继续通过；浏览器页面可打开并显示动态工作区数据。
6. **最小内核：** 现有 API 数据与客户端渲染；导航、状态流、详情分栏只是展示层。
7. **插件边界：** 行业包、模型、MCP/Codex 宿主状态从现有 API 读取；不在 UI 中创建新的执行器或行业角色。
8. **本地优先：** 页面只调用本机 Workspace API；模型密钥、工作内容和附件不写入源码或外部服务。
9. **数据分级：** UI 静态资源为 Public；工作项、成员和能力状态按 Sensitive 处理；凭证按 Restricted 处理。
10. **是否公开发布：** 是，公开提交只包含静态资源、测试和文档。
11. **外发计划：** 推送审阅后的公开差异到已配置 GitHub；不提交截图中的项目数据、BOQ 或令牌。
12. **状态与检查：** 页面状态只反映 API 当前事实；API 不可用时显示错误，不伪造“已运行”或“已交付”。
13. **观测/推断/假设/事实：** 参考图是布局参考；能力、模型和工作区数据由本地 API 提供；“Codex 作为宿主执行”是既定接入约束。
14. **演进/验证/灰度/回滚：** 纯展示层增量改动；可回滚单次提交；桌面 Tauri UI 不受影响。
15. **WebUI：** Required；这是用户日常输入、查看和审批的主要入口，保持 `Open → Input → Execute → Result`。
16. **最简实现：** 复用原生 DOM/CSS 和现有 API，新增接入视图、详情布局和少量状态组件，不引入 React 或其他前端依赖。
17. **明确不做：** 不复制造价业务字段，不新增自动发布、模型配置写入、MCP 注册或审批绕过，不把截图中的示例内容写入默认数据。
