# Build Decision Record: 通用 Agent Ops 工作台入口

1. **真实任务：** 让 Sayelf Agent Ops 的默认工作台先接收行业/专业与工作内容，再给出最少岗位闭环；造价、自媒体、软件开发等行业包只作为可选示范与已注册执行能力。
2. **最接近的既有能力：** 现有 `workspace_api`、Router、Registry，以及 Tauri 的本地 `workforce_blueprint` 已有通用工作流蓝图；当前 WebUI 复用了通用外壳，却默认载入 BuildCostIQ 团队规格。
3. **Step 0 判定：** Integrate。
3a. **Execution Verdict：** GO。
4. **可度量差异：** 新初始化工作区只有一个通用负责人 `human.owner`，不再出现 `human.pm`、造价负责人或施工审批角色；WebUI 增加行业输入并把它传入只读路由预览与工作项提交。
5. **成功证据：** 通用模板可初始化；项目标识为 `P-SAYELF-AGENT-OPS`；工作台源码包含行业输入和“行业包仅为示范”提示；团队评估规格继续通过；API 路由回归覆盖 industry 字段。
6. **最小内核：** 通用工作区规格、行业/工作内容输入、现有确定性 Router 与证据链。
7. **插件边界：** media / engineering / software 等行业包仍是可选能力目录；未知行业只能形成建议，不能假称已有执行能力。
8. **本地优先：** 行业、工作内容、路由建议、凭证和工作成果均留在本机工作区；不新增模型或网络调用。
9. **数据分级：** 输入按 Sensitive 处理，凭证按 Restricted 处理；模板和源码为 Public；不提交用户工作内容、令牌或本机运行数据。
10. **是否公开发布：** 是，用户已授权更新 GitHub；仅发布审阅后的源码、模板、测试和文档。
11. **外发计划：** 仅向已配置 GitHub 仓库推送 Public 差异；提交前检查路径、令牌、数据库和本机输出。
12. **状态与检查：** 通用模板是可初始化状态；行业包能力按当前 Registry 检查；模板或 UI 改动后重跑工作区与全量评估。
13. **观测/推断/假设/事实：** BuildCostIQ 默认规格混入是历史事实；通用入口与行业产品分离是设计决策；未知行业可执行性仍是受限能力，不由 UI 推断为已激活。
14. **演进/验证/回滚：** 新模板与字段为向后兼容增加；旧默认工作区先归档再重建通用工作区；回滚提交和本地归档即可，团队评估规格只位于 `evals/fixtures`。
15. **WebUI：** Required；工作路径保持 `Open → Input → Execute → Result`，技术细节通过渐进披露隐藏。
16. **最简实现：** 复用现有 Python Workspace API 与静态 WebUI，增加一个 JSON 模板、一个可选参数和少量文案/输入字段。
17. **明确不做：** 不重写 Router，不新增编排框架，不把未知行业动态注册为可执行技能，不迁移或删除既有工作区数据。
