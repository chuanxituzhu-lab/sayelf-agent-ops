# Sprint 04：桌面里用上内核——生成标题与短视频脚本

> 状态：已完成（2026-10-09）。基线：074c5ab。

## 0. 一句话

在桌面应用里，交付物是“标题”或“短视频脚本”的工作单，可以直接交给内核执行：产出岗位生成并自检，独立审核岗位检查，不合格自动返工。短视频脚本是第二条真实技能，也是内核里第一条“上一步产出交给下一步”的技能链（大纲 → 脚本）。

## 1. 决策记录（按 sayelf-base 构建门禁）

1. 任务：让 Sprint 03 的模型技能在桌面里可用；接入第二条真实技能；验证多步骤之间的产出传递。
2. 最接近的已有能力：桌面三阶段媒体工作流（生成内容与平台发布包）、Sprint 03 的 `kernel-titles` 动作、桌面的逐次同意与密钥保管。
3. Step 0：**Integrate**。由交付物路由决定执行引擎；不新建界面框架，只在现有执行面板里加一个按钮。
4. 可度量差异：标题与短视频脚本带独立审核记录和自动返工；原有三阶段工作流行为不变。
5. 证据：`evals/test_sprint04.py`（V01–V06、K01–K04）、更新后的 `evals/test_sprint03.py`，Python 共 126 个测试全绿；`cargo check` 与 Rust 单元测试（3 个）通过；前端 `vite build` 通过。
6. 回滚：`git revert` 本次提交；无数据库变更。

## 2. 决策变更：媒体三阶段工作流暂不迁入内核

Sprint 03 文档曾计划把三阶段工作流整体迁入内核 Runtime。本次决定**暂缓**，理由：

- 审批这一最关键的规则已在 Sprint 03 统一，迁移不再带来安全收益。
- 三阶段工作流约 1000 行，含检查点、进程锁、断点续跑，且测试完整；整体迁移回归风险高，而桌面端到端行为无法在构建环境里实际点击验证。
- 二阶思考：当第二个依赖“检查点续跑”的内核任务出现时，再把检查点机制抽进内核，一次迁移两边受益；现在迁移只是搬家。
